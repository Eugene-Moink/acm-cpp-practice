# 01 · 新生赛题单与选拔方案（洛谷 · 面试赛 · 不限语言 · **按手写计划重排的 11 题**）

> 目标：**60 人参赛 → 面试赛选出 25 人**。二本院校大一，**只学了基本输入输出、循环（for / while）、分支判断**；本场考纲在此基础上加入 **一维数组、枚举、简单字符串、排序**——**这四块就是知识天花板**。
> **本版依据**：手写的 11 个题位规划（签到 / 条件判断 / for×2 / 字符串×3 / 一维数组×2 / 排序 / 防 AK）。**内容一道没丢**，只把顺序改成难度递增（见 2.0 的对应表）。
> **这是面试赛**：送分题多 ⇒ 比赛区分度低，**必须把比赛当"资格线"用**（建议"过 A~H 八题"），面试定 25 人（见第九节）。
> **硬约束**：① **不限语言**，但**每道题都必须能用纯 C 写顺**；② **知识点最难只到一维数组/排序/简单字符串**；③ **题量 11 题**；④ 赛制用乐多。
> 全部题目的官方标题、难度、数据范围已逐题核实（见 [luogu-difficulty-verify.md](../luogu-difficulty-verify.md)）。

## 〇、八条结论先说

1. **难度配比**：**签到 2 + 送分 4 + 基础功 3 + 分水岭 1 + 防 AK 1 = 11 题**。**前六题（A~F）都压在 CF 800~850**，让刚学完循环分支的人也有分拿；真正分层的只有 I、J、K 三道。
2. **手写计划全部落实**：签到 ×2（A、C）、条件判断（B）、for 循环 ×2（D 简单 / G 偏难）、字符串 ×3（F 简单 / J 特 / C 签到送分）、一维数组 ×2（E 简单 / H 中等）、排序（I，带条件）、防 AK（K）。见 2.0 的逐项对应表。
3. **知识范围**
   - **考**：输入输出（`scanf`/`printf`/`getchar`/`fgets`）、**for 与 while 循环**、分支判断、一维数组（含数组标记、桶数组、char 数组）、**枚举**、**简单字符串（C 范围）**、**排序（冒泡/选择；用 C++ 的 `sort` 也可以）**。
   - **不考**：函数与递归、结构体、指针、二维数组、二分、贪心套路、DP、搜索、栈/队列、图论、KMP/哈希。
4. **11 道题里 10 道只需一个 `main`**（不用函数、结构体、指针、二维数组）；只有 I（排序 + 多关键字）在 C 里需要小心一点，但用**两个平行一维数组同步冒泡**就能写，仍然不需要结构体。
5. **数组规模全部很小**：需要排序的 I 只有 n ≤ 1000，冒泡足够，**不需要 `qsort`/快排**。
6. ⚠️ **尾部天花板约 CF 1200~1300**（防 AK = P5019）。在这个知识范围内，难度只能靠**细节密度**和**一个思维小跳跃**堆起来；要更高就必须让 DP/二分/图论进来。
7. **难度阶梯**：800 → 800 → 800 → 800 → 800 → 850 → 900 → 950 → 1000 → 1100 → 1300。
8. ⚠️ **区分度低，靠"资格线 + 面试"**：预计 35 人以上能做出 7~8 题。**比赛只负责筛掉基础不过关的，面试负责挑出 25 人。**

### 2.2 难度骨架

```
CF   ~800 ── A 签到（输入输出）        ┐
     ~800 ── B 条件判断 + 循环         │
     ~800 ── C 签到送分（字符串）      │ 前六题压在 800~850
     ~800 ── D for 循环（简单，买铅笔：不需要数组） │ 让新生都拿得到分
     ~800 ── E 一维数组（简单）        │
     ~850 ── F 字符串（简单）          ┘
     ~900 ── G for 循环（偏难，枚举 + 双重循环）
     ~950 ── H 一维数组（中等，桶数组）
     1000 ── I 排序 + 第二关键字
     1100 ── J 字符串（特，整词匹配 + 位置）
     1300 ── K 防 AK（数组 + 一个洞察，暴力 70%）
```

- **A~E 是"敢做区"（都压 800）**：绝大多数人都能过，作用是让新生拿到分、建立信心。
- **F~H 是基础功区**：认真上过课 + 写过作业的人应该都能过；这里区分"会不会自己写循环、数组、字符串"。
- **I、J、K 是分层区**：I 考排序细节，J 考字符串边界，K 考思维。**进面试的名单主要由这三道加 F~H 的部分分决定。**

### 2.3 I / J / K 三道"分层题"的坑点（验题时必须逐条走到）

| 题位 | 坑点 | 预期 AC / 60 |
|---|---|---|
| I 排队接水 | ① 按 **接水时间升序**排；② **时间相同时必须按编号升序**（题目要求"编号小的先接"，这是最经典的坑，写错直接 WA）；③ 输出**平均等待时间，保留 2 位小数**，累加要 `long long`（约 5e11，`int` 会溢出）；④ **已核实：n ≤ 1000**，冒泡排序足够，不用 `qsort` | 22~32 |
| J 统计单词数 | ① **已核实：文章长度 ≤ 10⁶、单词长度 ≤ 10**（C 里开全局 `char art[1000005]`，用 `fgets` 读一整行）；② **大小写不敏感**（统一转小写再比）；③ **整词匹配**——"word" 不能匹配 "sword"/"wordy"，必须判前后是不是空格或串首串尾；④ 输出"出现次数 + **首次出现的起始位置**"，位置从 **0** 开始、**空格占一位**；没出现输出 `-1` | 16~26 |
| K 铺设道路 | ① 正解 `ans = d[1] + Σ max(0, d[i] − d[i−1])`，**要能解释为什么**；② **暴力路线能拿 70%**（每次找最小非零段整体减，纯循环 + 数组），官方分档 30% / 70% / 100%——不会全盘吃零；③ **n ≤ 1e5（已核实）**，答案用 `long long` | 3~8 |

### 2.4 A~H 的坑点（验题时逐条走到）

| 题位 | 坑点 |
|---|---|
| A A+B | 有负数；**不能输出任何提示语** |
| B 不高兴的津津 | 读 7 组（在校时间、课外班时间），找**第一个**总和 > 8 的天并输出天数；**都不超过 8 要输出 0**；注意"第一个"和"最大的"不是一回事 |
| C 你的飞碟在这儿 | 两个**只含大写字母**的串；字母值 A=1…Z=26 连乘后 **mod 47**；相等输出 `GO`、否则 `STAY`；连乘要**边乘边取模**（不要先算完再取模）；C 里 `scanf("%s")` 读这两个串没问题（**没有空格**） |
| D 买铅笔 | **已核实：7 个数都 ≤ 10000 → int 足够**。三种包装（数量、价格），对每种算"要买几包"（**向上取整**：`(n + cnt - 1) / cnt`）再乘价格取最小；**读一组算一组即可，只用循环和条件，不需要数组**；题目**只允许买同一种包装**（不能混装）；有子任务分档，暴力枚举也能拿部分分 |
| E 校门外的树 | 区间是**闭区间** [l, r]，两端都要移走；树从 **0 号**开始，标记数组开到 10005 |
| F 标题统计 | 输入是**一整行**（可能含空格），统计**字母和数字**的个数，**空格与换行不计**；C 里用 `fgets` 或 `getchar` 读一行（`scanf("%s")` 会在空格处截断，**用错就 WA**） |
| G 计数问题 | **已核实：1 ≤ n ≤ 10⁶，x ∈ [0,9]**。枚举 1..n，对每个数**逐位拆开**数目标数字；注意 x 可以是 0；只用 int 就够（C 里约 7×10⁶ 次操作毫无压力） |
| H 明明的随机数 | **已核实：N ≤ 100、数值 ∈ [1,1000]**。先去重，再输出**去重后的个数**（不是原个数）；**桶数组 `cnt[1005]` 按值域扫一遍就是升序**，不需要排序 |

### 2.5 C 选手视角：每题在 C 里怎么写（**只需一个 `main`**）

| 题位 | C 写法要点 | 需要的数组 | 用到的知识 |
|---|---|---|---|
| A A+B | `scanf` 读两个数直接相加输出 | 无 | 输入输出 |
| B 不高兴的津津 | `for` 7 次读两数求和，`if (sum > 8)` 记下天数并 `break`（或标记） | 无 | 条件 + 循环 |
| C 你的飞碟在这儿 | `scanf("%s")` 读两串（无空格）；`for` 逐字符 `mul = mul * (c - 'A' + 1) % 47`，比较两个余数 | `char a[10], b[10]` | 字符串 + 取模 |
| D 买铅笔 | 三种包装各读一组（数量 `cnt`、价格 `price`），算 `((n + cnt - 1) / cnt) * price`，三次取最小 | 无 | for/分支（**不用数组**） |
| E 校门外的树 | 先把 0..L 全标 1，每个区间把标记清 0，最后数还有几个 1 | `int t[10005]` | 数组标记 |
| F 标题统计 | `while ((c = getchar()) != EOF && c != '\n')`，用 `isalnum(c)` 判断后计数 | 可不用数组 | 字符串 + 逐字符 |
| G 计数问题 | 外层 `for i=1..n`，内层 `while` 拆每一位，等于目标数字就计数 | 无 | 枚举 + 双重循环 |
| H 明明的随机数 | 读一个数就 `cnt[x] = 1`，再从 1 扫到 1000，**边统计个数边输出** | `int cnt[1005]` | 数组（桶）+ 枚举值域 |
| I 排队接水 | **两个平行数组 `t[]`、`id[]` + 冒泡**：比较时先比时间、时间相同比编号，交换时要**两个数组一起换**；再累加等待时间求平均 | `int t[1005], id[1005]` | 排序 + 贪心 |
| J 统计单词数 | `fgets` 读两行；两串都转小写（`tolower`）；遍历文章每个位置，用 `strncmp`（或逐字符）比单词，再判前后是不是空格/串首串尾 | `char w[15], art[1000005]` | 字符串 + 枚举位置 |
| K 铺设道路 | 读进数组后一行循环：`ans += (d[i] > d[i-1] ? d[i]-d[i-1] : 0)`，答案 `long long` | `int d[100005]` | 数组 + 循环 |

**结论**：11 道题**没有一道需要 `qsort`、动态数组、结构体、函数、指针或二维数组**；唯一需要排序的 I 题 n ≤ 1000，冒泡足够。头文件只有 `<stdio.h>`，字符串题再加 `<string.h>` 与 `<ctype.h>`。

### 2.7 知识点授权表（**每道题只能用"到它为止已出现的知识点"解决**）

> 规则：**没标"数组/排序"的题位，不允许依赖一维数组（数组标记、桶计数、先把数据全部存下来再处理）**；标了数组的题位才可以用数组。

| 题位 | 授权知识点（到此为止） | 该题实际需要 | 用数组吗 | 是否合规 |
|---|---|---|---|---|
| A 签到 | IO + 分支 | 读两个数相加 | ❌ 不用 | ✅ |
| B 条件判断 | + 循环 | 边读边判（7 次读数，一次只留一个和） | ❌ 不用 | ✅ |
| C 字符串签到 | + 字符 | 读字符、字母转值、连乘取模（可全程 `getchar`） | ❌ 不用 | ✅ |
| D for（简单） | + for | 三次枚举取最小花费 | ❌ 不用 | ✅（**本轮从 P1046 换成 P1909 就是为了这条**） |
| E 一维数组（简单） | **+ 一维数组** | 标记 0..L | ✅ 用 | ✅ |
| F 字符串（简单） | + 字符/整行 | `getchar` 逐字符统计 | ❌ 不用 | ✅ |
| G for（偏难） | + 嵌套循环 | 枚举 + 拆位 | ❌ 不用 | ✅ |
| H 一维数组（中等） | + 一维数组 | 桶数组去重 | ✅ 用 | ✅ |
| I 排序 | **+ 数组 + 排序** | 两个平行数组 + 冒泡 | ✅ 用 | ✅ |
| J 字符串（特） | 字符串（含 `char[]`） | 一整天文章要读进来 → `char` 数组 | ⚠️ **只用字符数组**，不用 int 数组 | ✅（见下方说明） |
| K 防 AK | 全部已授权 | 读数组后一趟扫描 | ✅ 用 | ✅（排在数组/排序之后） |

**两处边界要说清**：

1. **J（统计单词数）必须把文章读进来**（长度 ≤ 10⁶），所以它用 `char` 数组。这里的口径是：**"字符数组"算"字符串"知识点，不算"一维数组"知识点**——否则所有字符串题都无法成立（C 里字符串就是 `char[]`）。它**不需要任何 int 数组**，所以不越"数组"这条线。
   · 如果你要求连 `char` 数组都不许用：它可以用 `getchar` 流式做（边读边匹配 + 记位置），但实现难度会明显上升；或者换题。
2. **K（防 AK）需要 int 数组**——它排在第 11 位，前面 E/H/I 已经授权了数组与排序，**不违反"渐进"要求**。

## 三、难度锚点与选拔线

### 3.1 预期分数分布（乐多赛制）

| 名次区间 | 预期过题情况 | 预期得分率 | 备注 |
|---|---|---|---|
| 1~2 | A~J 全过 + K 拿到分 | 92%~100% | 少数有基础的人 |
| 3~10 | A~J | 82%~94% | 认真上完课 + 课外练过 |
| 11~20 | A~H/I | 70%~85% | **面试区上沿** |
| 21~35 | A~E/F | 55%~72% | **同分区（会很挤）** |
| 36~50 | A~D | 35%~58% | 会语法，细节不稳 |
| 51~60 | A~B | 15%~40% | 基础不牢 |

> ⚠️ **本版最大风险是"太挤"**：预计 35 人以上能做出 7 题，第 20~40 名的分差往往只来自一两道细节题和提交次数。**所以资格线要往上提，并且一定要配面试。**

### 3.2 建议的选拔口径：比赛当资格线，面试定人

| 方案 | 做法 | 适用 |
|---|---|---|
| **A（推荐）** | **资格线 = 过 A~H 八题**（前八题都是基础题，八题才算基础过关），或"总分前 40 名"，两者取并集；面试定 25 人 | 本版送分题多，必须用八题线才切得出争议 |
| B | 比赛取前 35~40 名进面试 | 报名人数明显超过 60 时 |
| C | 比赛分 + 面试分加权（如 5:5） | 想让比赛与面试各占一半 |

**为什么推荐资格线 + 面试**：前八题对认真做完作业的人都不难，用它决定谁进谁出说服力不足；但用它筛掉"连 A~H 都做不出来"的人非常有效。**面试才是真正的选拔。**

### 3.3 破平规则

**同分不加试**：同分者一起进面试。若必须在比赛层面排序：总分 → 过题数 → 最后一题 AC 时间 → 总罚时。

### 3.4 赛后废题自检

| 实测 AC 率 | 判定 | 动作 |
|---|---|---|
| > 90% | 只能是 A~D | 若非 A~D，下场换掉或加坑 |
| 60%~90% | 良好（E~H 应落这里） | 保留 |
| **20%~60%** | **最佳区分区（I 应落这里）** | 保留，看得分分布是否连续 |
| < 20% | 偏难（J、K 应落这里） | K 低于 3% 就换备选池里更软的题 |

另外单独统计：**K 题拿到 70% 部分分的人数**、**第 20~40 名的并列人数**（超过 10 人说明下次必须再加一道细节题）。

## 四、语言与规则

### 4.1 语言：不限，且**必须确认"只会 C 也能写"**

洛谷支持 C / C++ / Python3 / PyPy3 / Java 等，**默认语言是 C++14**。按官方规则，非 C/C++/Pascal 不保证时限、也不额外放宽。本套题里**只有 G 题（P1980，n ≤ 10⁶）需要留意**：C 里约 7×10⁶ 次操作毫无压力，但 CPython 暴力可能接近时限——公告里提一句即可；其余 10 题数据规模都极小（最大的是 K 的 n ≤ 1e5，一趟 O(n) 循环）。

**关键一条**：公告里明确写"**只会 C 的同学放心，11 道题全部可以用纯 C 写出来，不需要任何高级库**"。

### 4.2 提交前仍要提醒的一件事

**C 与 C++ 是两套编译**：用 C++ 语法却把语言栏选成 C 会 CE。试机题让每个人**用自己打算用的语言**交一次。

### 4.3 不发模板

组织方**不统一发放任何模板**，只允许自备纸质材料。

**边界**：公告里可以讲**规则与考纲**（C 与 C++ 是两套编译、C 里没有 `sort`/`string`、排序要自己写冒泡），但**不要给任何代码骨架**。

### 4.4 赛前可以公开的"考纲"（不公布题目）

| 会考 | 具体到哪一层 |
|---|---|
| 输入输出 | `scanf` / `printf`（`%d` / `%lld` / `%.2f`）、`getchar` 逐字符、`fgets` 读一整行 |
| 循环 | `for`、`while`、嵌套循环；用 `while` 拆数字的每一位 |
| 分支 | `if` / `else if` / `switch`、逻辑与或非 |
| 数组 | 一维数组的定义、下标、遍历；**数组标记**；**桶数组计数**；`char` 数组存字符串 |
| **枚举** | 在有限范围内逐个试：枚举 1..n、枚举值域、枚举每一个位置 |
| **简单字符串** | `char[]` + `strlen` / `strcmp` / `strncmp` / `fgets` / `tolower`（`<ctype.h>`）；逐字符处理 |
| **排序** | 冒泡 / 选择排序（写在数组上）；也可以用 C++ 的 `sort`；**会考"多关键字"**（先按一个关键字，相同再按另一个） |
| 其他 | 取模与整除、`long long` 的使用 |

**明确不考**：函数与递归、结构体、指针、二维数组、二分、贪心套路、动态规划、搜索、栈/队列、图论、KMP/哈希。

## 九、比赛 → 面试的衔接（**本方案的核心**）

### 9.1 为什么这场比赛必须配面试

本版前八题都是基础题，**区分度低**：预计 35 人以上能做出 7 题，第 20~40 名会挤在一起。用这种比赛硬切"第 25 名"，一天之内就会有人拿数据来找你。**正确做法：把它当资格线（过 A~H 八题），面试定人。**

### 9.2 面试手里有什么材料

**洛谷比赛的创建者/团队管理员能看到所有提交者的代码**。直接调出他比赛时的代码问：

| 想考察的 | 直接这样问 |
|---|---|
| 是否本人写的 | "你这题交了 8 次，前 7 次错在哪？" / "你 CE 了两次，什么原因？" |
| **条件判断** | "B 题如果 7 天都不超过 8 小时，你输出什么？为什么是 0 不是 7？" |
| **字符串功底** | "F 题你为什么用 `getchar` 而不是 `scanf(\"%s\")`？用 `%s` 会怎样？" / "J 题怎么保证 word 不会匹配到 sword？前后边界怎么判？" |
| 数组能力 | "H 题你为什么用桶数组而不是排序？桶要开多大？" |
| **排序细节** | "I 题时间相同的时候你怎么保证编号小的在前？你比较函数是怎么写的？" |
| **思维上限（最重要）** | "K 题你怎么做的？如果是暴力，你觉得哪一步做了重复工作？"（**暴力拿 70% 的人，追问这一句就能看出上限**） |

### 9.3 面试评分表（每项 1~5 分）

| 维度 | 看什么 | 权重 |
|---|---|---|
| 代码解释 | 能不能讲清自己代码的每一行（循环变量、数组下标、字符串边界、比较条件） | 高 |
| 调试过程 | 卡住时怎么定位（打印中间结果 / 自己造例子） | 高 |
| **思维上限** | K 题是"想到了"还是"只能暴力"，追问后能否自己推进 | 高 |
| 边界意识 | 主动想到 0、相等、闭区间、串首串尾、同分 | 中 |
| 表达与沟通 | 讲得清不清楚 | 中 |
| 动机与投入 | 赛前练过多少、接下来怎么练 | 低 |

> 每人 **8~12 分钟**（3 分钟讲一道自己的题 + 5 分钟追问 + 2 分钟动机），40 人建议 3~4 个面试官并行。

### 9.4 面试是防 AI 的最后一道闸

本套题都是经典题、网上题解极多，**AI 也能一次写对**。让他**当场解释代码的循环条件、数组下标、字符串边界和排序比较条件**，再**当场改一行**（比如删掉 I 的第二关键字、删掉 J 的前后空格判断、把 K 的 `> d[i-1]` 改成 `<`），基本就能分辨。
